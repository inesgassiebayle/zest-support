# Zest storytelling

The method lives in `skills/storytelling.md`. **Read it first**, then the files
it points to as the step needs them:

- `skills/storytelling/frameworks.md` — structures (last thing first, sparkline,
  SCAR, feature → value card).
- `skills/storytelling/personas.md` — the personas and the demo data.
- `skills/storytelling/demo-kit.md` — output format, Zest failure map,
  checklists, question bank, rehearsal mode.
- `docs/product.md` — pitch, problem, KPIs, scope, what is built.

## Read as the task requires
- `frontend/src/features/` in the `zest` app repo, if it is cloned next to this
  one — **read only**, never modify that repo. If it is not available, ask
  instead of assuming a feature exists.
- `design/zest/Zest.dc.html` — screens and their copy.
- `skills/project-management.md` — numbers, when the audience is the steering
  committee.

## Non-negotiable
- Ask the missing questions first (audience, time, presenters, what changed),
  at most four, in one message.
- Only demo what is done and in production; anything else is "what's next".
- Never pitch an out-of-scope feature. No number without a source.
- Answer in Spanish.
